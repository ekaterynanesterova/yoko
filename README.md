# Кухня Yoko

Учебный тренажёр по меню Yoko Sushi для работы на кухне: граммовки риса и количество кусков по типам, составы блюд в порядке выкладки, соусы, заготовки и раскладка сет-меню по коробкам.

**Живая версия:** https://ekaterynanesterova.github.io/yoko/

## Что внутри

| Вкладка | Зачем |
|---|---|
| Каркас | 8 типов с граммовками, 10 правил, таблица «семейств» — база, из которой собрано остальное меню |
| Соусы | 15 соусов с колонкой «где используется» + позиции с дипом на выбор гостя |
| Блюда | 85 позиций, ингредиенты в порядке выкладки, поиск по немецкому и русскому, фильтры |
| Заготовки | 18 карточек: рис, уксусная смесь, мисо-фонд, темпура, Cocktailmayo, кожа лосося, курица |
| Меню и коробки | Размер упаковки и комплект для 16 сет-меню, состав каждого, снеки. Свёрстана под печать A4 |
| Тренировка | Карточки и тест, 4 режима, прогресс сохраняется |

## Источники

- **Yoko Sushi Handbuch, Anhang 1 «Rezepturen»** (Stand 06/24) и **Anhang 2 «Verpackungsrichtlinien»** — граммовки, порядок ингредиентов, раскладка коробок.
- **webshop.yoko.de** — актуальная карта: позиции, появившиеся после 06/24.

Где источники расходятся, в интерфейсе стоит пометка (Yoko Rolls: 4 или 5 кусков; Inari Natur: Sweet Sauce или Teriyaki).

## Файлы

```
index.html    разметка
styles.css    оформление, обе темы + печать A4
data.js       все данные: глоссарий, типы, блюда, соусы, заготовки, меню
progress.js   прогресс тренажёра, слияние между устройствами
sync.js       Supabase REST, вход и синхронизация
app.js        отрисовка, тренажёр, вкладки
sw.js         офлайн-режим
supabase.sql  таблица прогресса — выполнить один раз
```

Правки меню — только в `data.js`. Блюдо описывается так:

```js
["io", "Alaska Roll", "Аляска", ["Avocado","Lachs"], [], [], ["fish"]]
//  тип   немецкое      русское    внутрь            сверху  соус  метки
```

Метки: `veg` `fish` `meat` `fried` (есть жареный компонент) и `deepfried` (ролл целиком уходит во фритюр — по этой метке рисуется значок ФРИ и работает раскраска «по жарке»). Русские подписи ингредиентов берутся из глоссария `G` в начале файла — новый продукт достаточно добавить туда один раз.

Во вкладке «Блюда» цветная ячейка — то, что кладётся внутрь, белая — то, что идёт сверху. Это повторяет оформление печатных техкарт.

## Синхронизация

Прогресс тренажёра хранится в `localStorage`. Если войти (кнопка «синхронизация»), он дополнительно уезжает в Supabase и подтягивается на других устройствах — аккаунт общий с KALORIYA.

Отметки хранятся как `ключ → время`, сброс режима пишет метку в `cleared`. Поэтому сброшенный прогресс не воскресает, когда подключается устройство со старой копией.

Без входа всё работает офлайн и никуда не отправляется.

## Деплой

```bash
git push origin main
```

GitHub Pages пересобирает за ~минуту. Service worker берёт файлы сначала из сети, поэтому новая версия приходит сама при следующем открытии — вручную ничего поднимать не нужно. Кэш нужен только для работы без интернета.

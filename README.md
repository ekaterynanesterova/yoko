# Кухня Yoko

Учебный тренажёр по меню Yoko Sushi для работы на кухне: граммовки риса и количество кусков по типам, составы блюд в порядке выкладки, соусы, заготовки и раскладка сет-меню по коробкам.

**Живая версия:** https://ekaterynanesterova.github.io/yoko/

## Что внутри

| Вкладка | Зачем |
|---|---|
| Каркас | 8 типов с граммовками, 10 правил, таблица «семейств» — база, из которой собрано остальное меню |
| Соусы | 15 соусов с колонкой «где используется» + позиции с дипом на выбор гостя |
| Блюда | 89 показываемых позиций. Ингредиенты в порядке выкладки, закладки по разделам, поиск (в том числе голосом) и фильтры |
| Заготовки | 18 карточек: рис, уксусная смесь, мисо-фонд, темпура, Cocktailmayo, кожа лосося, курица |
| Меню и коробки | Сет-меню карточками: состав по ячейкам с цветом по жарке, размер коробки, комплект. Нажатие на позицию открывает её рецепт. Свёрстана под печать A4 |
| Тренировка | Карточки и тест, 4 режима, прогресс сохраняется |
| Заказ | Фото кухонного чека → сборочный лист: что во фритюр, что крутить, коробки, комплект. Разбор через Gemini, ключ хранится в браузере. Есть ручная сборка без ключа |

## Источники

- **Yoko Sushi Handbuch, Anhang 1 «Rezepturen»** (Stand 06/24) и **Anhang 2 «Verpackungsrichtlinien»** — граммовки, порядок ингредиентов, раскладка коробок.
- **webshop.yoko.de** — актуальная карта: позиции, появившиеся после 06/24, и целиком разделы, которых нет в папке: снеки, десерты, супы, салаты, Don Yoko, вок. Напитки и стаканчики с соусами намеренно не переносились.

Где источники расходятся, в интерфейсе стоит пометка (Yoko Rolls: 4 или 5 кусков; Inari Natur: Sweet Sauce или Teriyaki).

## Файлы

```
index.html    разметка
styles.css    оформление, обе темы + печать A4
data.js       все данные: глоссарий, типы, блюда, соусы, заготовки, меню
photos.js     карта «позиция → картинка», собрана скриптом
img/          миниатюры блюд и меню, img/box — раскладки коробок
progress.js   прогресс тренажёра, слияние между устройствами
sync.js       Supabase REST, вход и синхронизация
scan.js       чек → Gemini, словарь названий для точного разбора
order.js      хранение заказов и разворачивание в сборочный лист
app.js        отрисовка, тренажёр, вкладки
sw.js         офлайн-режим
supabase.sql  таблицы прогресса и заказов — выполнить один раз
```

Правки меню — только в `data.js`. Блюдо описывается так:

```js
["io", "Alaska Roll", "Аляска", ["Avocado","Lachs"], [], [], ["fish"]]
//  тип   немецкое      русское    внутрь            сверху  соус  метки
```

Метки: `veg` `fish` `meat` `fried` (есть жареный компонент) и `deepfried` (ролл целиком уходит во фритюр — по этой метке рисуется значок ФРИ и работает раскраска «по жарке»). Русские подписи ингредиентов берутся из глоссария `G` в начале файла — новый продукт достаточно добавить туда один раз.

Во вкладке «Блюда» ячейка с заливкой — то, что кладётся внутрь, прозрачная — то, что идёт сверху. Это повторяет оформление печатных техкарт.

Сет-меню лежат в `MENUCARDS`. Позиция описывается как `[штук, немецкое название, обсыпка]`, где название **должно совпадать** с полем `de` в `D` — по нему подтягиваются русское имя и признак `deepfried` для цвета. Позиции, которых нет в `D` (супы, салаты, снеки), описываются в `SET_EXTRA`. Если сумма по списку не сойдётся с полем `pcs`, карточка сама покажет предупреждение — так нашлось расхождение в Peanut Pokal Menü.

## Ассортимент филиала

Тренажёр настроен на **Yoko Castrop-Rauxel**, Biesenkamp 25, 44575 (store id `188` в каталоге Yoko). В базе лежат все 145 позиций и 34 меню, но показывается только то, что есть в этом филиале: **89 блюд и 28 меню**. Данные не удалены — это фильтр витрины.

Основание — два независимых источника: поле `storeIds` в каталоге Yoko и печатная брошюра филиала. Они совпали почти полностью: по премиум-роллам, нигири, летним роллам, поке-боулам, супам и салатам — ровно позиция в позицию.

Вернуть: блюдо — убрать из `HIDDEN`, меню — из `HIDDEN_MENUS`, раздел целиком — снять `off:true` у типа в `TYPES` (сейчас скрыты `don` и `special`).

## Фото

Связь «позиция → картинка» взята **из каталога Yoko** (в `article-info` у каждой статьи свой `images[]`), а не подобрана по названию. Все 142 фото блюд и 31 фото меню просмотрены глазами и сверены с описанием.

- **142 блюда из 145** с фото. Нет у Maki California, Sushi Burger Chicken, Maki Tempura Spargel.
- **31 меню из 34.** Нет у Fitness Menü, Happy Sushi Menü, Big Yoko Menü — но у всех троих есть фото коробки.
- **16 раскладок коробок** вырезаны из Handbuch, Anhang 2. Ещё шесть снимков на страницах 13, 14, 15, 16, 17 и 20 идут без заголовка, поэтому не подписаны — заголовок в папке стоит только над верхним фото.

Миниатюры лежат в репозитории (~2 МБ) и работают офлайн. По нажатию открывается полный размер: у меню — раскладка коробки, у блюд — оригинал 1920×1080 с сервера Yoko, то есть только онлайн. Их CDN не умеет отдавать уменьшенные копии, поэтому ссылаться на него ради миниатюр нельзя — вышло бы 12 МБ на одну вкладку.

Пересобрать миниатюры: скачать оригиналы по ссылкам из `photos.js` и ужать до 170×170 (блюда, квадрат по центру) и 260×146 (меню).

## Синхронизация

Прогресс тренажёра и снятые чеки хранятся в `localStorage`. Если войти (кнопка «синхронизация»), он дополнительно уезжает в Supabase и подтягивается на других устройствах — аккаунт общий с KALORIYA.

Отметки хранятся как `ключ → время`, сброс режима пишет метку в `cleared`. Поэтому сброшенный прогресс не воскресает, когда подключается устройство со старой копией.

Без входа всё работает офлайн и никуда не отправляется.

## Голосовой поиск

Кнопка микрофона в поле поиска использует встроенное в браузер распознавание речи (`SpeechRecognition`) — **ни ключа, ни наших серверов**. Рядом переключатель языка: по умолчанию `DE`, потому что названия блюд немецкие, но поиск ищет и по русскому, так что `RU` тоже работает. Выбор запоминается.

Нужен интернет и разрешение на микрофон. В Firefox распознавания нет — там кнопка просто не появляется, поиск руками работает как раньше. Учти, что в Chrome звук уходит на серверы Google: это встроенное поведение браузера, не наша отправка.

## Разбор чека

Фото чека уходит в Gemini (`gemini-2.5-flash`) вместе со **списком всех позиций карты**. Модель не угадывает буквы — она выбирает из готового списка, поэтому смазанный шрифт термопринтера почти не мешает. Что не совпало ни с чем, попадает в блок «не распознано», а не выдумывается.

Ключ Gemini вводится один раз кнопкой «Ключ Gemini» и лежит только в `localStorage` этого браузера — **в репозиторий он не попадает**. Фото никуда не сохраняется, в облако уезжает только разобранный состав заказа.

Сборочный лист разворачивает меню в конкретные роллы и складывает одинаковые, а считает **в роллах, а не в кусках**: 2× Maki Menü дают не «16 штук Maki Sake», а «2 ролла, режем по 8 кусков, всего 16». Так понятно, сколько крутить и как резать. Нигири и летние роллы лепятся поштучно и не режутся — у них в `TYPES` нет `cut:true`, поэтому показываются штуками.

Группировка идёт по порядку работы: сначала фритюр, потом крутка, потом «как складывать». Последний блок даёт **по карточке на каждое заказанное меню**: раскладка коробки фотографией, размер коробки, комплект **на одну коробку** (васаби, имбирь, соусы) и состав. Внизу общий итог по коробкам, чтобы взять их сразу.

Кнопка «Собрать вручную» делает то же самое без ключа и без интернета: пишешь «2 Maki Menü, Yoko Roll Lachs, 3 Gyoza Chicken» — получаешь тот же лист.

## Деплой

```bash
git push origin main
```

GitHub Pages пересобирает за ~минуту. Service worker берёт файлы сначала из сети, поэтому новая версия приходит сама при следующем открытии — вручную ничего поднимать не нужно. Кэш нужен только для работы без интернета.
